# 사카두 v0.11.0 · Windows 화면 수정 지시서

분석 기준은 2026-11-27 확인한 최신 정식 릴리스 **v0.11.0**이다. 릴리스 태그와 GitHub 기본 브랜치 `main`이 모두 `bc30f281f1fef7fae817cdc014587fbf449c3467`을 가리켰다. 아래 경로는 저장소 루트 기준이다. 첨부 화면과 해당 커밋의 소스를 대조했다. Windows에서 직접 확인해야 할 입력·표시 현상은 3번과 8번에 재현 절차를 적었다. [릴리스](https://github.com/noddish/sakadu/releases/tag/v0.11.0) · [기준 소스](https://github.com/noddish/sakadu/tree/bc30f281f1fef7fae817cdc014587fbf449c3467)

Claude Code에서 작업할 때는 1·7번의 드라이브 행을 함께 수정한다. 4·6·8번은 9번의 영역 계산을 공유하므로, 각각 다른 좌표나 폭을 저장하지 않도록 한다. 공통 렌더러와 저장 형식을 수정하면 macOS 시제품의 기존 호출부도 확인한다.

## 1. 드라이브의 남은 용량이 ‘수정한 날짜’에 표시됨

**확인된 원인.** 첫 화면의 `Windows (C:)` 행에는 날짜 열에 `193 GB 사용…`, 크기 열에 `1.8 TB`가 보인다. `src/shell.rs`의 `list_drives`는 `GetDiskFreeSpaceExW`가 반환한 호출자 기준 가용 바이트를 `Entry.free`에, 전체 바이트를 `Entry.size`에 담는다. `src/ui/paint.rs`의 `paint_pane_list`가 `cols.modified`를 그리면서 드라이브에 `"{} 사용 가능"`을 출력한다. 따라서 화면의 193 GB는 **남은 용량**이다. [드라이브 조회](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/shell.rs#L611) · [날짜 열 분기](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/ui/paint.rs#L427)

**수정.** 드라이브 행의 날짜 셀을 비우고, 가용량과 총량은 7번에서 같은 크기 셀에 배치한다. 날짜를 채우려고 디스크 루트의 수정 시각을 새로 조회하지 않는다. 일반 파일·폴더는 기존 `format_time_short`와 `format_time_fit`을 사용한다.

**완료 확인.** `내 PC → 자세히`에서 날짜 열을 넓히거나 좁혀도 드라이브 날짜 칸은 비어 있고, 유형에는 `로컬 디스크`가 표시된다. 파일이 있는 폴더로 이동해 짧은 날짜·긴 날짜 설정과 날짜 정렬을 확인한다. 행 렌더링 테스트는 드라이브 한 줄의 **날짜 셀 좌표**에 용량 텍스트가 그려지는지도 검사한다.

## 2. 강조색을 바꾸면 창 바탕까지 바뀜

**확인된 원인.** `src/app/settings_ui.rs`의 `Ctl::Accent`는 `look.accent`를 바꾼다. `src/app/workspace_ui.rs`의 `accent_key`는 현재 작업 공간의 지정색을 우선한다. 실제 변색은 `src/palette.rs`의 `Theme::resolve`에서 일어난다. `window, strip, field, hover, sel_inactive, border, pane_border, thumb`에 강조색을 밝은 테마에서 4%, 어두운 테마에서 6% 섞는다. 버튼 바탕 `control`도 `window`에서 파생된다. 파일 목록의 `pane`은 이 혼합 대상에 들어 있지 않다. [팔레트 계산](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/palette.rs#L145)

**수정.** 창·설정 바탕, 입력 칸, 테두리와 기본 버튼은 테마의 중립색에서 계산한다. 강조색은 활성 탭, 활성 선택 행, 포커스, 켜진 컨트롤 및 작업 공간 아이콘처럼 상태를 나타내는 곳에 적용한다. 기존 `accent_soft`·`sel`·`chip_text` 계산과 운영체제 고대비 분기를 살린다. `docs/sakadu-style-sheet.md`의 ‘강조 색에서 계산하는 것’에도 기존 4%·6% 혼합이 명시돼 있으므로 해당 규칙을 함께 맞춘다.

**완료 확인.** 같은 테마·같은 작업 공간에서 전역 강조색을 따르도록 두고 파랑에서 주황으로 바꾼다. 빈 창 바탕·설정 바탕·입력 칸·기본 버튼의 색은 동일하고 활성 선택색은 바뀌어야 한다. 밝음·어두움, 자체 색을 지정한 작업 공간, 재시작 후 복원을 확인한다. 팔레트 테스트는 중립색의 값이 강조색 선택 간에 같은지, 버튼과 창의 명도 차 및 선택 글자 대비가 충분한지 각각 검사한다.

## 3. 왼쪽 위 사카두 로고 클릭 시 창이 사라짐

**확인할 경로.** 두 번째 화면의 흰 로고는 첫 작업 공간 아이콘 위에 있는 창 아이콘이다. `src/app/caption.rs`의 `nc_hit`가 `app_icon_rect` 주변을 `HTSYSMENU`로 돌려주고, `src/main.rs`는 처리되지 않은 비클라이언트 입력을 `DefWindowProcW`에 넘긴다. 현행 코드 주석상 한 번 누르면 창 메뉴, 두 번 누르면 닫기다. `src/app/messages.rs`의 `WM_CLOSE`는 트레이 대기가 켜져 있으면 창을 숨기고, 꺼져 있으면 닫는다. **단일 클릭이 실제로 종료를 일으키는지는 미확인**이다. [로고 입력 판정](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/app/caption.rs#L67) · [닫기 처리](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/app/messages.rs#L241)

**재현 후 수정.** Windows에서 `sakadu.exe --log`로 실행한다. 트레이 대기 켬·끔 각각에서 로고 중앙을 한 번 누른 뒤 손을 떼고 기다린다. 빠른 두 번 클릭은 별도로 시험한다. 창이 사라지면 트레이 복원 여부, 프로세스 생존 여부, `%TEMP%\sakadu.log`의 `close: hide to tray` 또는 `close: destroy window`를 대조한다. 정상 닫기 기록 없이 프로세스가 사라질 때는 예외 기록도 확인한다. **제안 동작은 로고 한 번으로 창 메뉴를 한 번 열고, 로고를 연속해서 눌러도 명시적 닫기 선택 전에는 창을 유지하는 것**이다. 기본 시스템 메뉴에 전달된 연속 입력이 원인이면 로고 영역의 처리만 조정한다. 창 전체의 `WM_CLOSE`를 막으면 우측 닫기와 트레이 동작까지 깨진다.

**완료 확인.** 로고 클릭 후 메뉴를 취소하고 원래 탭에서 탐색을 계속할 수 있다. 로고 연속 클릭, 인접한 작업 공간 버튼 및 다른 배율에서도 확인한다. 창 메뉴의 ‘닫기’, 우측 위 ×, Alt+F4는 기존 트레이 설정대로 동작하고 빈 제목 표시줄의 드래그·더블클릭도 작동해야 한다.

## 4. 사이드바 헤더의 고정 핀을 상시 보이는 접기 버튼으로 교체

**확인된 원인.** `src/app/sidebar.rs`의 `paint_side_panel`은 `hot || floating`일 때만 `side_pin_rect`에 핀을 그린다. `sidebar_hit`에는 같은 사각형의 `Hit::SidePin` 판정이 남아 있다. `side_toggle_pin`은 고정을 풀고 `side_peek`를 남기므로 한 번 눌러도 패널이 열린 채일 수 있다. 대상은 ‘기본’ 같은 작업 공간 이름 옆의 **패널 헤더**다. 세 번째 화면 경로 줄의 책갈피는 현재 폴더를 저장하는 `Hit::Star`다. [그리기 조건](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/app/sidebar.rs#L980) · [패널 상태 전환](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/app/sidebar.rs#L380)

**수정.** 작업 공간 패널이 열려 있으면 헤더 끝에 `접기` 버튼을 항상 그린다. 버튼의 클릭 영역과 툴팁도 같은 사각형과 상태를 쓴다. 클릭은 `close_side()`를 통해 고정·임시 열림 상태를 정리한다. 명시적으로 접은 직후 호버 타이머가 패널을 다시 열지 않도록 확인한다. 접은 뒤에는 레일의 현재 작업 공간 아이콘을 눌러 다시 펼친다. 6번에서 레일을 이동해도 두 동작을 사용할 수 있어야 한다.

**완료 확인.** 포인터와 키보드 포커스를 파일 목록으로 옮겨도 열린 패널의 접기 버튼이 보인다. 고정해서 연 패널과 잠시 띄운 패널이 각각 한 번에 닫힌다. 고정 패널이 차지하던 폭은 즉시 파일 목록에 돌아간다. 다시 펼쳤을 때 작업 공간, 고정한 폴더 및 활성 탭을 확인한다.

## 5. 작업 공간마다 사용자가 고른 아이콘 표시

**현재 구현.** 두 번째 화면의 파랑·보라 버튼은 작업 공간이다. `src/ui/rail.rs`의 `RailSpace`에는 색과 분할 레이아웃만 있고 `paint_rail`은 선택·비선택·고대비 상태에서 모두 `draw_layout_icon`을 호출한다. `src/app/workspace_ui.rs`의 `show_rail_menu`와 `src/workspaces.rs`의 `Workspace` 저장 형식에도 아이콘 선택이 없다. [레일 그리기](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/ui/rail.rs#L45) · [작업 공간 저장 형식](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/workspaces.rs#L152)

**수정.** 각 공간의 우클릭 메뉴에 `아이콘 바꾸기…`와 `기본 아이콘으로 복원`을 둔다. 선택은 메뉴를 연 공간의 인덱스에 적용한다. 사용자 지정의 구현안은 **로컬 이미지 파일 선택**이며, 첫 지원 형식으로 투명 PNG를 제안한다. 파일을 정상적으로 읽은 후 앱 데이터에 보관하고 `workspaces.txt`의 해당 공간에 선택적 아이콘 식별자를 저장한다. 그릴 때마다 원본 파일을 읽지 않는다. 아이콘이 미지정이거나 읽을 수 없으면 기존 분할 그림을 사용한다. 선택 테두리와 드롭 표시는 사용자 이미지 바깥에서도 식별할 수 있게 유지한다.

**완료 확인.** A·B 두 공간에서 B를 활성화한 채 A의 우클릭 메뉴로 아이콘을 바꾼다. A에만 새 아이콘이 보이고 A의 분할 수를 바꿔도 아이콘은 유지된다. 원본 파일 이동, 재시작, 선택 취소, 기본값 복원, 아이콘 키가 없는 구버전 저장 파일을 확인한다. 저장소의 기존 색·탭·고정 위치가 함께 복원되어야 한다.

## 6. 작업 공간 아이콘 모음을 창의 상·하·좌·우에 배치

**현재 구현.** 제보의 이동 단위를 **작업 공간 아이콘 모음 전체**로 해석한다. `src/ui/rail.rs`의 `rail_geom(top, bottom, …)`은 왼쪽 한 열을 전제로 한다. Windows에서는 `src/app/sidebar.rs`의 `rail`·`panes_left`·`side_panel_rect`·`side_resize_rect`, `src/app/layout.rs`의 `hit_with`, `src/app/dragdrop.rs`의 드롭 판정, `src/app/paint.rs`의 툴팁 위치가 이 전제를 각각 사용한다. [공통 레일 좌표](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/ui/rail.rs#L32) · [Windows 패널 좌표](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/app/sidebar.rs#L157)

**수정.** 화면 설정에 왼쪽·오른쪽·위·아래를 넣고, 기본은 왼쪽으로 둔다. 위치는 `src/session.rs`의 전역 화면 설정으로 저장한다. `apply_screen`으로 다른 작업 공간을 복원해도 사용자가 정한 위치를 유지한다. 좌우에선 세로, 상하에선 가로로 아이콘을 배치한다. 레일 사각형을 한 번 계산해 그리기·클릭·호버·우클릭·드롭·툴팁에 전달한다. 펼친 패널과 본문은 9번의 가용 사각형을 쓰고, 상단 배치에서는 로고·창 조절 버튼·제목 표시줄의 드래그 영역을 별도로 확보한다.

**완료 확인.** 네 방향을 차례로 바꾸며 공간 전환, 새 공간 추가, 설정, 파일 끌어다 놓기, 4번의 접기·펼치기를 시험한다. 예전 왼쪽 레일 자리의 파일도 정상적으로 클릭되어야 한다. 짧은 변에 공간을 전부 표시할 수 없을 때 현재 공간과 기존 공간 목록 접근 경로를 유지한다. 작업 공간 전환·앱 재시작 후 위치가 유지되고, 구버전 설정은 왼쪽으로 열린다.

## 7. ‘내 PC’의 드라이브 크기에 사용률 게이지 표시

**현재 구현.** `src/ui/start.rs`의 `paint_start`에는 드라이브 타일 게이지가 이미 있다. 채움은 `1 − free / total`이고 사용률 90% 초과 시 색이 달라진다. `내 PC → 자세히`의 `paint_pane_list`는 크기 열에 총량만 쓴다. `src/pane.rs`의 기본 크기 열은 84 DIP이고, `src/ui.rs`의 `columns`는 목록 폭이 460 DIP 미만이면 크기 열을 숨긴다. [기존 게이지](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/ui/start.rs#L315) · [열 표시 조건](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/ui.rs#L325)

**수정.** 총량이 있는 드라이브의 크기 셀에 사용률 막대를 그리고, 넓으면 `193 GB 사용 가능 / 전체 1.8 TB`처럼 두 수치의 뜻을 표시한다. 기본 폭에서는 총량과 작은 막대를 우선하고, 셀이 좁거나 숨겨지면 행 툴팁으로 두 수치를 읽을 수 있게 한다. `src/app/paint.rs`의 기존 `Hit::Row → name_tip`이 제공하는 긴 이름도 함께 보존한다. 비율은 포맷 전 바이트로 계산해 0~100% 범위로 제한한다. 조회 실패·총량 0은 ‘용량 정보 없음’으로 처리하고, 총량이 유효하며 가용량이 0이면 사용률 100%다. 현재 행 데이터로 그려서 스크롤·다시 그리기 때마다 디스크를 재조회하지 않는다.

**완료 확인.** 가용량/총량이 `100/100`, `50/100`, `0/100`일 때 각각 빈 막대, 절반, 가득 찬 막대가 보인다. 용량 미확인 드라이브는 이 세 상태와 식별된다. 창을 좁혀 크기 열이 사라져도 수치를 확인할 수 있고, 넓히면 크기 열에 다시 나타난다. 일반 파일에는 기존 파일 크기를 표시하며 크기 정렬은 원래 바이트 값 기준으로 동작해야 한다.

## 8. 분할 칸을 다시 넓혔을 때 상단 폴더 탭 이름 복원

**확인된 부분.** 세 번째 화면에서 오른쪽 경로에는 `내 PC`가 보이는데 상단 탭은 `내…`이고 우측 항목 수도 잘려 보인다. 대상은 목록의 ‘이름’ 열 위에 있는 **상단 폴더 탭**이다. `src/app/layout.rs`의 `chips`는 그릴 때마다 원래 제목을 측정한다. 공통 `tab_natural_w`는 글자 너비에 양쪽 여백과 필요 시 닫기 버튼 자리를 더한 뒤 최대 180 DIP로 제한한다. `tab_rects`의 축소 분기는 다른 탭을 위한 최소 폭을 빼며, 탭이 하나인 경우에도 이 계산에 들어갈 수 있다. **180 DIP 상한은 긴 이름을 설명하지만 짧은 ‘내 PC’의 원인은 따로 확인해야 한다.** [탭 폭 배분](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/ui.rs#L376) · [실제 제목 그리기](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/ui/paint.rs#L170)

**재현 후 수정.** 두 칸으로 나누고 오른쪽에 `내 PC` 단일 탭을 연다. 처음 넓을 때의 화면과 분할선을 당겨 좁혔다가 **같은 최종 폭**으로 돌린 화면을 비교한다. 창 자체를 줄였다 키우는 경우도 확인한다. `chips`가 받은 칸 너비, `head_right_w`가 예약한 항목 수 너비, `tab_rects` 결과, 패딩을 뺀 라벨 영역과 `Font::Normal` 실측값을 같은 프레임에서 대조한다. Windows `src/gfx.rs`의 `text_w`는 일부 글자 모드에서 양 끝을 픽셀에 맞춘다. 배율별로 최종 그리기 폭이 실측보다 좁아지는지도 확인한다. 탭마다 현재 제목에 필요한 폭을 계산하고, `+`·항목 수·실제로 표시할 다른 탭을 뺀 잔여 폭까지 늘어날 수 있게 한다. 단일 탭에는 이웃 탭 몫을 예약하지 않는다.

**완료 확인.** 탭을 다시 선택하거나 창을 새로 열지 않아도 원래 폭에 돌아오는 즉시 `내 PC`와 `7개`가 온전히 보인다. 자연 폭이 180 DIP를 넘는 긴 한글 이름도 실제 공간이 충분하면 전부 보인다. 탭이 많거나 폭이 부족하면 말줄임이 가능하되 활성 탭·추가·닫기·탭 끌기 영역이 겹치지 않는다. 100%·125%·150% 배율에서 짧은 이름과 긴 이름 모두 확인한다.

## 9. 각 영역이 실제 배정받은 크기로 다시 배치되도록 수정

**수정 지점.** `src/app/layout.rs`의 `area`는 최소 100 DIP를 강제하고, `src/ui.rs`의 `chip_strip`도 우측 필터·항목 수를 빼고 다시 최소 100 DIP를 확보한다. 부모가 실제로 내줄 공간보다 넓어질 수 있다. `columns`는 목록 폭 300·460·590 DIP에서 날짜·크기·유형을 차례로 표시하지만, 사용자가 넓혀 둔 열의 폭을 그대로 빼면 이름 열과 겹칠 수 있다. `src/app/layout.rs`의 `cols`는 이미 `DATE_AUTO`와 `date_col_w`로 자동 날짜 폭을 계산한다. 이 값과 사용자가 저장한 열 폭, 현재 화면에서 적용할 폭을 구별한다. [창과 분할 칸](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/app/layout.rs#L12) · [탭 줄과 목록 열](https://github.com/noddish/sakadu/blob/bc30f281f1fef7fae817cdc014587fbf449c3467/src/ui.rs#L305)

| 영역 | 배치 규칙 | 확인할 결과 |
| --- | --- | --- |
| 창 → 파일 칸 | 제목·도구 막대, 6번 레일, 고정 패널, 미리 보기의 실제 점유 폭·높이를 뺀 사각형에서 `pane_rects`와 `splitters`를 계산한다. 임시로 떠 있는 패널은 겹쳐 그리는 상태로 처리한다. | 패널을 접거나 레일을 옮기면 빈 공간을 즉시 사용한다. 분할선의 그려진 자리와 드래그 자리가 같다. |
| 칸 → 탭·경로 | 각 칸의 머리에서 버튼·개수·필터의 폭을 확보한 뒤 탭과 경로에 남은 폭을 준다. 부모 밖으로 나가는 최소 폭 강제를 없앤다. | 한쪽 분할선만 움직여도 양쪽이 각자 새 폭을 반영한다. 짧은 쪽의 줄임이 넓은 쪽까지 전파되지 않는다. |
| 칸 → 목록 열 | 별도로 저장된 선호 폭을 현재 칸에 맞춰 줄이거나 기존 우선순위로 열을 숨긴다. 헤더·행·열 경계 드래그가 같은 결과를 쓴다. | 임시 축소 후 넓히면 사용자 지정 열 폭과 자동 날짜 설정이 복원되고, 7번 게이지가 인접 셀에 그려지지 않는다. |
| 그리기 → 입력 | `hit_with`, 탭 드롭, 스크롤, 툴팁, `src/app/edits.rs`의 `layout_edits`가 사용하는 주소·필터 입력창에 같은 최종 사각형을 전달한다. | 표시된 버튼·탭이 그 자리에서만 눌린다. 숨긴 버튼이 파일 클릭을 가로채지 않고 입력창이 다른 칸을 덮지 않는다. |

**완료 확인.** 창 크기 변경, 창 크기를 유지한 분할선 이동, 사이드바 접기·펼치기, 미리 보기 열기·닫기, 배율·글꼴 변경을 각각 검증한다. 한 칸에서 네 칸까지 대표 분할 모양을 시험한다. 최소 창에서 긴 탭·필터·큰 열 폭을 조합한 뒤 넓혀도 겹침이 없고, 처음부터 동일한 크기로 연 경우와 최종 배치가 같아야 한다.
